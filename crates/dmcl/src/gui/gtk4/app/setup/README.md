# 首次启动向导

`crates/dmcl/src/gui/gtk4/app/setup` —— 配置文件不存在时，由根组件在启动后打开的设置向导。
整体架构见 [app/README.md](../README.md)，GTK4 前端见 [gtk4/README.md](../../README.md)。

## 入口与生命周期

- 根组件启动时检查 `<配置目录>/dmcl/dmcl.json`：只有文件**不存在**（`NotFound`）才创建
  `SetupWizard`；权限错误等其它情况交给配置警告处理。
- 向导是一个模态 `AdwDialog`，由根组件持有控制器并保活。组件在 `init` 里用一次
  `idle_add_local_once` 把对话框 `present` 到主窗口上，等窗口和启动期提示先显示。
- `AdwDialog` 关闭 `can-close`：Esc 和标题栏关闭按钮不能绕过确认。离开向导只有两条路：
  点「完成」，或点「跳过」并在确认框里选择「跳过」。
- 完成后根组件丢弃控制器；向导自己先关闭对话框。

## 三步

| 步骤 | 内容 | 复用 |
| --- | --- | --- |
| 账户 | 账户列表、添加离线账户、Microsoft 设备代码登录、设为默认、删除 | `AccountPage` |
| Minecraft 目录 | 目录列表、添加 / 编辑 / 删除、星标设为默认、拖动排序 | `DirectoryPage` |
| 游戏设置 | 「版本隔离」`AdwSwitchRow`，对应 `launch.version_isolation` | 向导内的单行表单 |

账户页和目录页直接作为 `GtkStack` 的两个子页面，不复制登录、目录校验等逻辑。两个页面仍然
读写同一个 `ConfigStore`；根组件收到配置变更后会通知向导重新计算完成条件。

标题栏固定为「设置向导」，不显示步骤序号。底部是「跳过」「返回」「下一步 / 完成」；
最后一步不再显示「跳过」，只保留「返回」和「完成」。账户步骤只有在 `launch.account`
指向一个存在的账户时才能点「下一步」；最后一步在账户或默认目录无效时禁用「完成」。
缺少账户时不额外显示红字提示。

## 跳过与保存

- 「跳过」先弹 `AdwAlertDialog`：「设置尚未完成，确认跳过？」。选择继续则留在向导，
  选择跳过则把当前配置原样写入文件并关闭向导。最后一步没有「跳过」按钮，但按 Esc 等关闭
  尝试仍会走同一个确认框（`close-attempt` 信号）。
- 「完成」同样先调用 `ConfigStore::save`，保存成功后才关闭对话框并上报
  `SetupOut::Finished`；保存失败时留在向导里显示错误，可以重试。
- 跳过也会写配置，因此下次启动不会再出现向导。配置文件在此期间被删除时，向导会重新出现。

## 完成后的主页

`SetupOut::Finished` 交给根组件处理：

- 先按配置补齐新目录的主页；
- 当前 `minecraft_root` 与启动时的主页不同时，关闭启动时的初始主页标签；
- 打开或聚焦新默认目录的主页。

`SetupOut::Skipped` 不切换主页。

## 测试

`finish_block_reason` 是纯逻辑：默认账户缺失 / 指向不存在的账户，或默认根目录无效时返回
提示文案。单测覆盖这几种完成条件；步骤导航和控件行为不创建 widget。
